# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Arcadium is a cross-platform arcade-cabinet frontend: a Godot 4 .NET UI that launches emulators, fed by a C# CLI scanner that indexes local ROM/media folders into SQLite. Everything is C#/.NET 10 (SDK pinned in `global.json`); scenes/themes are Godot files. All repo content (code, comments, docs, strings) is written in English.

## Commands

```bash
dotnet build Arcadium.sln                                    # builds Core + Scanner
dotnet run --project src/Arcadium.Scanner -- --help          # scanner CLI
dotnet run --project src/Arcadium.Scanner -- scan update --config config
dotnet run --project src/Arcadium.Scanner -- scan update --config config --check-configuration
dotnet run --project src/Arcadium.Scanner -- import-mame --xml <listxml.xml> --db <path>
dotnet run tools/scripts/lookup-rom.cs mame zookeep          # throwaway lookup script (run from repo root)
```

There is no test project. For manual verification, use the file-based scripts in `tools/scripts/` (single `.cs` files with a `#:project` reference to Core; no csproj needed).

`TreatWarningsAsErrors` is on with `AnalysisLevel=latest-recommended` (see `Directory.Build.props`) and applies to every `.cs` file in the tree, including `tools/scripts/`. Expect analyzer errors like CA1305 (pass `CultureInfo.InvariantCulture`) to fail the build.

The Godot project (`src/Arcadium.Godot/`) is not in the solution; its csproj is generated by the Godot .NET editor when opening `project.godot`. It is currently an empty shell (no C# code yet).

## Setup

Real config files are gitignored (machine-specific paths). Copy `config/cabinet.example.json` → `config/cabinet.json`, and likewise one file per system/emulator in `config/system-profiles/` and `config/emulator-profiles/`. The SQLite database path comes from `cabinet.json`'s `database` field. Never commit ROMs, artwork, database files, or real cabinet paths.

## Architecture

Three projects with a strict direction: `Arcadium.Scanner` (CLI host) and the future Godot UI both depend on `Arcadium.Core` (all logic); nothing depends on the hosts.

**Data flow:** JSON config (`ConfigReader` + `ConfigValidator`, source-generated JSON via `ArcadiumJsonContext`) → `ScanEngine` walks ROM folders per system and upserts into SQLite → the Godot UI reads that database and launches emulators via a safe argument list (never a shell command). MAME metadata is a separate flow: `mame -listxml` output → `MameXmlImporter` → `mame_*` tables.

**Database layer (`src/Arcadium.Core/Data/`):**
- `SqliteDatabase` is the connection factory: `OpenReadWrite()` (WAL) for the scanner, `OpenReadOnly()` for frontends.
- Migrations are `.sql` files in `database/migrations/`, embedded as resources in Core's csproj and applied by `MigrationRunner` — deliberately **not** run on every connection open; hosts invoke it explicitly (see `Arcadium.Scanner/Program.cs`).
- Repositories follow a caller-owns-the-connection pattern: constructor takes an open `SqliteConnection`; explicit `BeginTransaction`/`Commit`/`Rollback` where writes happen. `ScanRepository` (roms/scan_runs writes + change-detection read), `MameRepository` (bulk import with cached prepared commands, plus `GetMachineByName` lookup), `LibraryRepository` (read-only frontend lookups returning `LibraryRom`).
- All SQL is raw strings with `$param` placeholders and manual ordinal mapping (`IsDBNull` guards). No ORM — keep it that way unless explicitly decided otherwise.

**Key schema fact:** `roms.basename` (scanned file name without extension) joins to `mame_machines.name` — that is how a scanned file gets its MAME metadata (description, year, controls, rom dumps). A rom without a match (console systems, unknown sets) simply has no machine; use LEFT JOIN / null semantics. Rom rows are never hard-deleted by `scan update`; they get `scan_state = 'deleted'`, so reads must filter on `scan_state = 'active'`.

**Scanner CLI:** commands `scan [init|update|verify]` and `import-mame`; change detection uses size + mtime (no file hashing). With `--json`, stdout is reserved for NDJSON `ScanEvent`s — this is the planned IPC protocol for the Godot UI, so never print anything else to stdout in that mode.

**Code conventions** (visible throughout Core): file-scoped namespaces, `sealed` classes, `ArgumentNullException.ThrowIfNull` / `ArgumentException.ThrowIfNullOrWhiteSpace` guards on public members, XML doc comments on public types stating ownership/transaction semantics, static `Logger` facade for logging, model class `System` aliased as `GameSystem` to avoid the namespace clash.

## Code style

`.editorconfig` in the repo root is authoritative: all proposed code must comply with it. Read it before writing code. Note in particular that `var` is not used — always write explicit types.
